# 检索与重排

检索器把 query 变成候选 Document。框架提供 `EnhancedRetriever` 统一入口，用开关区分纯向量检索与父子检索；重排是可选的精排开关。

## 1. EnhancedRetriever 统一入口

```java
DocumentRetriever retriever = EnhancedRetriever.builder()
        .vectorStore(vectorStore)          // 必填：LangChain4j EmbeddingStore<TextSegment>
        .embeddingModel(embeddingModel)    // 必填：embedding 模型
        .documentStore(documentStore)      // 父子召回时必填
        .topK(5)                           // 召回数量，默认 5
        .minScore(0.3)                     // 最低相似度，可选
        .filter(filter)                    // LangChain4j Filter，可选
        .enableParentChild(true)           // 开关：true 父子召回，false 纯向量
        .build();
```

`builder` 参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| vectorStore | EmbeddingStore<TextSegment> | 是 | 向量库 |
| embeddingModel | EmbeddingModel | 是 | embedding 模型 |
| documentStore | DocumentStore | 父子召回时 | 父块库 |
| topK | int | 否 | 召回数量，默认 5 |
| minScore | Double | 否 | 最低相似度，不传则不过滤 |
| filter | Filter | 否 | LangChain4j 过滤表达式 |
| enableParentChild | boolean | 否 | 是否父子召回，默认 false |

行为：

- `enableParentChild=true`：命中子块后按 parentChunkId 回查父块完整小节，多子块命中同一父块自动去重
- `enableParentChild=false`（默认）：纯向量召回

父子分块数据用父子召回，普通分块数据用纯向量检索。

## 2. 过滤表达式

调用方用 LangChain4j 的 `MetadataFilterBuilder` 构造 filter：

```java
import dev.langchain4j.store.embedding.filter.Filter;
import dev.langchain4j.store.embedding.filter.MetadataFilterBuilder;

// 单条件
Filter filter = MetadataFilterBuilder.metadataKey("docType").isEqualTo("aicube");

// 否定条件（如排除父块）
Filter notParent = MetadataFilterBuilder.metadataKey("skipEmbedding").isNotEqualTo("1");
```

`MetadataFilterBuilder` 提供 `isEqualTo` / `isNotEqualTo` / `isGreaterThan` / `isLessThan` / `isIn` / `isNotIn` 等谓词；多个条件可通过 LangChain4j 的逻辑谓词（`And` / `Or` / `Not`）组合。

filter 字段需注意 Redis 与 PG 的差异（见存储篇）：PG 任意字段可过滤，Redis 需注册过的字段。

## 3. 重排（可选开关）

```java
Reranker reranker = new HttpReranker(
        baseUrl, apiKey, model, topK,
        HttpReranker.RequestFormat.DASHSCOPE);   // 或 RequestFormat.FLAT
```

`HttpReranker` 参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| baseUrl | String | 是 | rerank 服务地址 |
| apiKey | String | 是 | 服务密钥 |
| model | String | 是 | rerank 模型名 |
| topK | int | 是 | 精排后截断数量 |
| requestFormat | RequestFormat | 否 | 请求体格式，默认 FLAT |

`RequestFormat` 两种：

- `FLAT`（默认）：`{model, query, documents, top_n}`，适配 Jina / Cohere / OpenAI
- `DASHSCOPE`：`{model, input:{query,documents}, parameters:{top_n}}`，适配阿里百炼

重排对检索候选集做 query-document 相关度二次打分取 topK。不传则跳过，不影响主流程。

## 4. 框架接管 vs 调用方传递

| 职责 | 谁负责 |
|------|--------|
| 父子回查、去重、向量检索 | 框架 |
| 传向量库/父块库、topK / threshold / filter | 调用方 |
| 重排 HTTP 调用、按分数排序 | 框架 |
| 传 rerank 服务地址/密钥/模型 | 调用方 |
