# 查询增强

查询增强在检索前把用户问题改造成更适合检索的形态。框架自建 `QueryTransformer`（1→1）/ `QueryExpander`（1→N）接口，并提供快速构建工厂。

## 1. 四种增强器

| 增强器 | 作用 | 接口 |
|--------|------|------|
| compression | 结合对话历史消解指代，合成独立 query | QueryTransformer（1→1） |
| rewrite | 去口语/冗余，单轮改写 | QueryTransformer（1→1） |
| hyde | 先生成假设答案，用假设答案检索 | QueryTransformer（1→1） |
| expand（multiQuery） | 1→N 生成多个语义变体 | QueryExpander（1→N） |

## 2. 快速构建工厂

```java
ChatModel chatModel = ...;

QueryTransformer compression = QueryTransformers.compression(chatModel);
QueryTransformer rewrite      = QueryTransformers.rewrite(chatModel);
QueryTransformer hyde         = QueryTransformers.hyde(chatModel);
QueryExpander    multiQuery   = QueryExpanders.multiQuery(chatModel);
```

参数（均只需传入 ChatModel）：

| 工厂方法 | 参数 | 说明 |
|---------|------|------|
| QueryTransformers.compression(chatModel) | ChatModel | 默认压缩提示词 |
| QueryTransformers.rewrite(chatModel) | ChatModel | 默认改写提示词 |
| QueryTransformers.hyde(chatModel) | ChatModel | 默认 HyDE 提示词 |
| QueryExpanders.multiQuery(chatModel) | ChatModel | 默认配置（重载可指定变体数与是否包含原问题） |

需要自定义提示词时，HyDE 转换器可直接传入提示词模板：

```java
QueryTransformer hyde = new HydeQueryTransformer(chatModel,
        "自定义提示词模板，占位符 {query}");
```

其它增强器或非标逻辑，直接实现 `QueryTransformer` / `QueryExpander` 接口即可；`QueryExpanders.multiQuery` 也提供 `(chatModel, numberOfQueries, includeOriginal)` 重载。

## 3. 选择建议

- **compression 与 rewrite 二选一**，不必同时启用。多轮对话用 compression（消解指代），单轮用 rewrite
- hyde、expand 可按需叠加，顺序由调用方在 pipeline 中指定

## 4. 问题澄清

问题澄清（clarify）不做成 RAG 组件，因为澄清是「中断 + 反问用户 + 等答案」，属于 Agent 运行时能力，不是检索链路的纯变换。Agent 模式下由 core 的 `AskUserTool`（HITL）承担，在 agent 提示词中引导即可。

## 5. 框架接管 vs 调用方传递

| 职责 | 谁负责 |
|------|--------|
| 默认提示词、LLM 调用 | 框架（快速工厂） |
| 传入 ChatModel、选择启用哪些增强器 | 调用方 |
| 自定义提示词 | 调用方（覆盖默认） |

## 6. 验证样例

`samples` 模块 `rag/RagPgRetrieveTest.java` 与 `rag/RagRedisRetrieveTest.java`，检索方法中全量启用了 compression + hyde + multiQuery。
