# 思考模型适配

部分模型支持「思考模式」，会在输出中返回推理过程（思考内容）和正式回答。不同厂商的思考模型通过不同方式返回推理内容，框架通过 `ThinkingMode` 枚举统一适配。

## 三种模式

| 模式 | 说明 | 适用模型 |
|------|------|---------|
| `DISABLED`（默认） | 不处理思考内容，自动剥离 `content` 中的 `<think/>` 标签 | 普通模型 |
| `THINK_TAG` | 思考内容嵌入在 `content` 字段中，用 `<think/>` 标签包裹 | MiniMax M2.7 等 |
| `REASONING_CONTENT` | 思考内容通过独立的 `reasoning_content` / thinking 字段返回，`content` 只有正文 | DeepSeek V4、Qwen3.6-plus、GLM 等 |

## 配置方式

通过 `thinkingMode()` 指定模型的思考内容输出格式：

```java
// DeepSeek / Qwen3.6-plus — reasoning_content 格式
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .thinkingMode(ThinkingMode.REASONING_CONTENT)
        .build();

// MiniMax — <think/> 标签格式
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .thinkingMode(ThinkingMode.THINK_TAG)
        .build();

// 普通模型（默认，不处理思考内容）
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .build();
```

> **开启思考的入参由调用方负责**：不同模型开启思考的请求参数不同（如 Qwen 的 `thinking_enable`、DeepSeek 的 `thinking.type`），调用方在创建 `ChatModel` 时自行配置，框架只负责解析输出。

> **REASONING_CONTENT 建议统一走 OpenAI 兼容客户端**：LangChain4j 的 `OpenAiChatModel` 原生解析 `reasoning_content` 字段（`returnThinking(true)`，写入 `AiMessage.thinking()`）。各厂商只要提供 OpenAI 兼容接口即可接入，无需专用模块：
> ```java
> // GLM 通过 OpenAI 兼容接口访问（支持 reasoning_content）
> ChatModel chatModel = OpenAiChatModel.builder()
>         .baseUrl("https://open.bigmodel.cn/api/paas/v4")
>         .apiKey("your-api-key")
>         .modelName("glm-4.7")
>         .returnThinking(true)
>         .build();
> ```
> DeepSeek V4 使用框架内置工厂 `DeepSeekV4ChatModel`，详见 [14-DeepSeek-V4兼容](14-DeepSeek-V4兼容.md)。

## 事件流

开启 `thinkingMode` 后，流式输出中会多出 `Thinking` 事件：

```java
agent.streamForResult("帮我分析这段代码的复杂度", RunnableParams.empty())
        .doOnNext(event -> {
            if (event instanceof AgentStreamEvent.Thinking t) {
                System.out.println("[思考] " + t.content());    // 模型推理过程
            } else if (event instanceof AgentStreamEvent.Text t) {
                System.out.print(t.content());                   // 正式回答
            }
        })
        .blockLast();
```

**开启 thinkingMode**：

```
[Thinking] 让我分析一下这段代码...     ← 思考过程（Thinking 事件）
[Text] 这段代码的时间复杂度是...       ← 正式回答（Text 事件）
[Complete]
```

**关闭（默认 DISABLED）**：

```
[Text] 这段代码的时间复杂度是...       ← 直接输出正式回答
[Complete]
```

## 关闭思考输出

使用普通模型（如 qwen-plus、glm-4.7）时不需要配置，默认就是 `DISABLED`。

如果使用思考模型但不希望看到思考过程，也保持默认即可：

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        // 不配置 thinkingMode，默认 DISABLED
        .build();
```

关闭时框架会自动处理：

- 在用户消息末尾追加 `<no_think>` 标签，提示模型不输出思考过程
- 如果模型仍然输出了 `<think/>` 内容，会自动剥离，不会出现在最终回答中

## 内部实现

### THINK_TAG 模式

框架通过 `ThinkTagParser` 工具类流式解析 `<think/>` 标签：

- 跨 chunk 状态追踪：通过 `inThink` 状态跟踪标签开关
- 支持 `<think/>` 和 `<think attr="..."/>` 等变体
- 处理跨 chunk 的不完整标签

### REASONING_CONTENT 模式

思考内容在流式期就由 LangChain4j 通过独立回调（`onPartialThinking`）传入，框架由 `ThinkingModeProcessor.processReasoningChunk` 直接分发，无需事后从消息 metadata / 反射字段提取：

- `reasoning_content` → `Thinking` 事件
- `content` → `Text` 事件
